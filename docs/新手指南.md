# PackingProof QQBot 新手指南

这份指南从零开始完成 QQ 官方机器人、PackingProof 和 QQBot 的连接。完成后，用户可在 QQ 私聊或已授权的 QQ 群中向机器人发送快递单号，机器人会查询并发送关联录像。

## 开始前先确认

- QQBot 只能运行在 Windows 电脑上，且机器人运行期间电脑不能关机
- PackingProof 主程序必须已经可以正常查看录像，并开启 Web 服务
- QQBot 与 PackingProof 可以在同一台电脑，也可以在同一局域网的两台电脑
- QQBot 不需要安装 .NET 或 FFmpeg。FFmpeg 只由 PackingProof 主机在需要压缩超限录像时使用
- 请准备一个用于管理机器人的 QQ 号，以及需要实际测试机器人的 QQ 号

## 第一步：在 QQ 开放平台创建机器人

1. 用浏览器打开 [QQ 机器人开放平台](https://q.qq.com/qqbot/)，登录管理机器人的 QQ 号
2. 进入“我的机器人”，按页面提示创建机器人，填写机器人名称和头像
3. 创建完成后，打开该机器人的“开发设置”
4. 在“AppID 接入凭证”中复制 **AppID**
5. 点击“查看 AppSecret”，复制 **AppSecret**，只在稍后的 QQBot 配置窗口中粘贴一次

AppSecret 相当于机器人的密码。不要发到 QQ 群、聊天记录、截图、公开文档或 Git 仓库，也不要填入 PackingProof 的网页访问密钥位置。

QQ 平台的页面名称和审核规则可能调整；遇到入口变化时，以开放平台中的“开发者开发文档”为准：<https://bot.q.qq.com/wiki/develop/api-v2/>

## 第二步：让测试 QQ 号可以找到机器人

在 QQ 开放平台的机器人“开发设置”页面：

1. 找到“开发体验号码设置”
2. 点击“添加用户”
3. 填入要测试的 QQ 号，保存
4. 用该 QQ 号搜索或通过机器人链接添加机器人，然后先私聊发送一条消息

开发体验用户不受正式服务范围限制，适合在发布前测试。机器人显示在线但完全不回复时，先检查该 QQ 号是否已经加入开发体验用户。

## 第三步：固定群使用时，只需配置群白名单

个人开发者后台目前可能没有可开启的“群能力”，也不需要为 QQBot 寻找或申请这个开关。只要已经能把机器人拉进目标群，并且在群里 `@机器人 单号` 后 QQBot 管理器的“运行日志”显示“收到 QQ 群消息”，群消息链路就已经可用。

此时固定群使用只差一个本机安全步骤：QQBot 必须把该群的群 OpenID 加入白名单。按“第七步”把管理器日志显示的 OpenID 加入即可。

白名单不会改变 QQ 平台的权限，但它是群里“机器人在线、管理器收到消息、却没有回复”最常见的原因。若根本无法把机器人拉进群，或 `@机器人` 后管理器完全没有“收到 QQ 群消息”，先确认机器人仍在群内且消息确实带有 `@机器人`；不要尝试非官方“QQ 挂机”或扫码登录方案。

## 第四步：准备 PackingProof 主机

在保存录像的 PackingProof 主程序中：

1. 打开“设置 → 扩展与联动”
2. 开启“启用扩展 API”
3. 确保主程序正在运行，并记住其地址

地址填写规则：

| QQBot 与 PackingProof 的位置 | 在 QQBot 中填写的地址 |
| --- | --- |
| 同一台电脑 | `http://127.0.0.1:5280` |
| 同一局域网的另一台电脑 | `http://PackingProof主机的IPv4地址:5280`，例如 `http://192.168.1.20:5280` |

不要在这里附加 `?key=...`，也不要填写录像网页链接。QQBot 会通过独立授权取得受限凭据，不使用网页访问密钥。

若局域网连接失败，先在运行 QQBot 的电脑浏览器中打开该地址；打不开时检查两台电脑是否在同一网段、PackingProof 的 Web 服务是否运行，以及 Windows 防火墙是否允许该端口的局域网访问。

## 第五步：首次启动 QQBot

1. 解压管理员提供的 QQBot Windows 发布包，保持所有文件在同一文件夹
2. 双击 `PackingProof.QQBot.exe`，会打开“PackingProof QQBot”管理器
3. 首次使用依次填写 QQ AppID、QQ AppSecret 和 PackingProof 地址。若不知道地址，可点击“搜索局域网主机”，选中自己的主机后点击“使用选中主机”
4. 点击“保存并授权”。PackingProof 会弹出授权窗口，确认 QQBot 申请的“录像查询、下载和交付副本”权限
5. 保存成功后机器人会自动连接 QQ，管理器下方会显示“正在连接 QQ 网关”。关闭窗口不会停止机器人，它会继续显示在 Windows 右下角系统托盘

敏感信息不会写进发布文件夹：QQ AppSecret 和扩展凭据由 Windows 当前用户加密保存。请在同一个 Windows 用户账户下运行 QQBot；换账户或换电脑后需要重新配置。

## 第六步：私聊查询录像

在已经添加机器人的 QQ 号中，直接发送完整快递单号，例如：

```text
SF1234567890
```

机器人会先回复找到的录像数量、录制时间、时长和文件大小，再上传录像。它不会搜索文件名、备注或商品名称，只按 PackingProof 中保存的订单标识查询。

QQ 对单条用户消息的被动回复次数有限。每一批最多发送 3 段录像；如果还有剩余，机器人会提示“还剩 N 段。回复‘继续’即可发送下一批”。直接回复“继续”即可从下一段接着发送，不会重复前一批。

## 第七步：把目标群加入 QQBot 白名单

首次将机器人加入目标群后：

1. 在群里 `@机器人` 并发送一个完整单号
2. 打开系统托盘中的 QQBot 管理器，查看“运行日志”中显示的群 OpenID
3. 在“QQ 群白名单”输入框粘贴该 OpenID，点击“添加”
4. 无需重启，之后再次在群里 `@机器人 单号` 即可查询

之后在这个群里使用 `@机器人 单号` 查询，发送 `@机器人 继续` 发送下一批。白名单是本机安全保护：即使机器人被拉进其他群，也不会在那里查询或发送录像。

## 视频大小与转码

在 QQBot 管理器的“视频发送”区域修改单个录像的发送上限，默认是 190 MB，可选 1 到 200 MB，然后点击“保存视频设置”。

- 未超过上限：直接发送原片
- 超过上限：默认保持原视频编码，由 PackingProof 主机按实际时长计算码率后生成临时副本
- 需要更小体积时：可选择转为 H.265
- 无论哪种情况：原始录像不会修改，不会自动切割成多段

若无法在不切割的前提下压进上限，机器人会说明原因。此时可提高上限、选择 H.265，或从 PackingProof 中人工取得原始录像。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 显示“PackingProof 尚未启用扩展 API” | 在 PackingProof 的“设置 → 扩展与联动”开启扩展 API |
| 配置时 HTTP 401 | 地址必须是纯主机地址，例如 `http://192.168.1.20:5280`；删除 `?key=...` 后重新配置 |
| 机器人在线但私聊不回复 | 将该 QQ 号加入 QQ 开放平台的“开发体验号码设置”，然后重新发完整单号 |
| 群里没有反应，但管理器日志显示“收到 QQ 群消息”或“发现未授权群” | 这是群 OpenID 尚未加入 QQBot 白名单。按“第七步”加入即可 |
| 群里没有反应，管理器日志也没有任何群消息 | 确认机器人仍在群内，并发送 `@机器人 单号`；个人开发者后台没有“群能力”开关时可直接忽略该项 |
| 提示未找到录像 | 先在 PackingProof 回放中确认该单号已经被写入对应录像。QQBot 不按视频文件名搜索 |
| 提示转发失败 | 保持机器人窗口开启，稍后重试；若提示文件超限，调整“视频发送设置”后再查一次 |
| 更换了 QQ AppSecret、PackingProof 地址或授权被撤销 | 打开管理器，重新填写信息并点击“保存并授权”，然后在 PackingProof 中重新批准授权 |

## 安全与维护

- 不要把 AppSecret、扩展凭据、`secrets.dat` 或 `settings.json` 发给他人
- 不要把 QQBot 运行在不受信任的公共网络
- 在 PackingProof 的“已授权扩展”中可以查看、轮换或撤销 QQBot 授权
- 需要停止机器人时，右键 Windows 系统托盘中的 QQBot 图标，选择“退出 QQBot”
- 更新 QQBot 时，先停止机器人，再用新发布包替换程序文件；本机配置和密钥不在发布目录中，不会随解压包覆盖

## 开机自动启动与主机地址变化

在管理器中点击“登录 Windows 后自动启动”即可启用。它只写入当前 Windows 用户的启动项，下次登录后机器人在后台运行并显示系统托盘图标，不会弹出命令行窗口。

首次授权时 QQBot 会记录 PackingProof 主机的稳定 `nodeId`。以后该主机 IP 发生变化时，QQBot 会先检查原地址，失败后在局域网中寻找完全相同 `nodeId` 的主机并自动更新地址。它绝不会自动换到另一台 PackingProof 主机；搜索到新主机后，仍需在管理器中明确选择并重新授权。
